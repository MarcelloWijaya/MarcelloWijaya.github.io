## Outstanding manual checks before future extensive redesigns
1. Browser test at 320, 375, 768, 1024, and 1440 px for overflow, long titles, and image crop.
2. Keyboard sequence: reach flip button, Enter/Space, Tab into back content, Escape to close; repeat with a touch screen.
3. Contrast and focus in both light/dark themes. Validate accessible names with screen reader.
4. Test actual external links and screenshot assets in an unrestricted browser; provider SSO may hide preview deployments.
5. Run Lighthouse in production for LCP, CLS, accessibility and SEO. No score is claimed in this report.
6. Acquire approved screenshots from the four projects; current company visual tiles are labeled typographic illustrations, not actual screenshots.

## Technical debt
- Source data for older projects is embedded in JSX; gradually extract it into data files.
- CSS is spread across layered historical stylesheets. Consolidate after a comprehensive browser regression pass.
- Legacy root `html/`, `css/`, and duplicate root `assets/` remain tracked; remove only after verifying GitHub Pages and Vercel routing consumers.
- Vercel is the canonical production host but GitHub Pages still runs in parallel. Confirm whether secondary publication is intentional.
- Case studies use hash routes, not crawlable independent paths. A future routing migration needs host fallback configuration and a plan for GitHub Pages.
